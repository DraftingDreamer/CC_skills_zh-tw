# Agent 設計模式

本文件涵蓋在 Claude API 上建構 agent 的決策啟發式方法：應選用哪些原語、如何設計工具介面，以及如何在長時間執行中管理情境與成本。工具的具體機制和程式碼範例請參見 `tool-use-concepts.md` 和各語言專屬資料夾。

---

## 模型參數

| 參數 | 使用時機 | 預期行為 |
| --- | --- | --- |
| **自適應思考**（`thinking: {type: "adaptive"}`） | 當您希望 Claude 自行控制思考的時機與深度時。 | Claude 依每個請求決定思考深度，並自動在工具呼叫之間穿插思考。無需調整 token 預算。 |
| **Effort**（`output_config: {effort: ...}`） | 在全面性與 token 效率之間調整取捨時。 | 較低 effort → 更少且更集中的工具呼叫、更少的前言、更簡短的確認。`medium` 通常是有利的平衡。當正確性比成本更重要時使用 `max`。 |

模型支援和參數詳情請參見 `SKILL.md` §思考與 Effort。

## 設計您的工具介面

### Bash 與專用工具的選擇

Claude 不了解您應用程式的安全邊界、審批政策或 UX 介面。Claude 發出工具呼叫；您的框架處理它們。工具呼叫的形狀決定框架能做什麼。

**bash 工具**給予 Claude 廣泛的程式控制力——它幾乎可以執行任何動作。但它只給框架一個不透明的命令字串，每個動作都是相同的形狀。將動作提升為**專用工具**，框架就有了帶有型別化引數的特定動作鉤子，可以攔截、控制、呈現或稽核。

**何時將動作提升為專用工具：**

- **安全邊界。** 需要控制的動作是天然的候選者。可逆性是個實用準則：難以復原的動作（外部 API 呼叫、傳送訊息、刪除資料）可以放在使用者確認的控制之後。`send_email` 工具容易控制；`bash -c "curl -X POST ..."` 則不然。
- **過期檢查。** 專用的 `edit` 工具可以在 Claude 上次讀取後檔案已變更時拒絕寫入。Bash 無法強制執行這個不變式。
- **呈現。** 有些動作受益於自訂 UI。Claude Code 將提問提升為工具，使其能以對話方塊方式呈現、提供選項，並阻塞 agent 迴圈直到回答為止。
- **排程。** 唯讀工具如 `glob` 和 `grep` 可標記為可並行安全。當相同動作透過 bash 執行時，框架無法區分可並行安全的 `grep` 和不可並行安全的 `git push`，因此必須序列化。

**經驗法則：** 一開始用 bash 取得廣度。當需要控制、呈現、稽核或並行化動作時，才提升為專用工具。

## Anthropic 提供的工具

| 工具 | 端 | 使用時機 | 預期行為 |
| --- | --- | --- | --- |
| **Bash** | 客戶端 | Claude 需要執行 shell 指令。 | Claude 發出指令；您的框架執行它們。提供參考實作。 |
| **文字編輯器** | 客戶端 | Claude 需要讀取或編輯檔案。 | Claude 透過您的實作檢視、建立和編輯檔案。提供參考實作。 |
| **電腦使用** | 客戶端或伺服器端 | Claude 需要與 GUI、網頁應用程式或視覺介面互動。 | Claude 截圖並發出滑鼠/鍵盤指令。可自託管（由您執行環境）或由 Anthropic 託管。 |
| **程式碼執行** | 伺服器端 | Claude 需要在您不想自行管理的沙盒中執行程式碼。 | Anthropic 託管的容器，內建檔案和 bash 子工具。無客戶端執行。 |
| **網路搜尋 / 擷取** | 伺服器端 | Claude 需要訓練截止日期後的資訊（新聞、時事、近期文件）或特定 URL 的內容。 | Claude 發出查詢或 URL；Anthropic 執行並回傳帶有引用的結果。 |
| **記憶體** | 客戶端 | Claude 需要跨 session 保存情境。 | Claude 讀寫 `/memories` 目錄。您實作儲存後端。 |

**客戶端**工具由 Anthropic 定義（名稱、綱要、Claude 的使用模式），但由您的框架執行。Anthropic 提供參考實作。**伺服器端**工具完全在 Anthropic 基礎設施上執行——在 `tools` 中宣告，Claude 處理其餘部分。

## 組合工具呼叫：程式化工具呼叫

使用標準 tool use 時，每次工具呼叫都是一次往返：Claude 呼叫工具、結果進入 Claude 的情境、Claude 推理後再呼叫下一個工具。三個依序動作（讀取設定檔 → 查詢訂單 → 檢查庫存）意味著三次往返。每次都增加延遲和 token，而大多數中間資料再也用不到。

**程式化工具呼叫（PTC）**讓 Claude 將這些呼叫組合成指令碼。指令碼在程式碼執行容器中執行。當指令碼呼叫工具時，容器暫停、呼叫被執行（客戶端或伺服器端），結果返回到執行中的程式碼——而不是 Claude 的情境。指令碼用普通控制流（迴圈、篩選、分支）處理結果。只有指令碼的最終輸出返回給 Claude。

| 使用時機 | 預期行為 |
| --- | --- |
| 許多依序工具呼叫，或大量中間結果您希望在進入情境視窗之前先篩選。 | Claude 撰寫將工具作為函式呼叫的程式碼。在程式碼執行容器中執行。Token 成本按最終輸出計算，而非中間結果。 |

## 擴展工具和指令集

| 功能 | 使用時機 | 預期行為 |
| --- | --- | --- |
| **工具搜尋** | 可用工具很多，但每個請求只有少數相關。不想在情境中預先載入所有綱要。 | Claude 搜尋工具集，只載入相關綱要。工具定義是附加而非替換——保留快取（見下方快取章節）。 |
| **Skills** | 僅在相關時 Claude 應載入的特定任務指令。 | 每個 skill 是帶有 `SKILL.md` 的資料夾。skill 的說明預設在情境中；當任務需要時，Claude 才讀取完整檔案。 |

兩種模式都保持固定情境小巧，按需載入詳細資訊。

## 長時間執行的 Agent：管理情境

| 模式 | 使用時機 | 預期行為 |
| --- | --- | --- |
| **情境編輯** | 情境在多輪後變得過期（舊的工具結果、已完成的思考）。 | 工具結果和思考區塊根據可設定的閾值清除。保持執行記錄簡潔而無需摘要。 |
| **壓縮** | 對話可能達到或超過情境視窗限制。 | 較早的情境在伺服器端摘要為壓縮區塊。關於關鍵的 `response.content` 處理，請參見 `SKILL.md` §壓縮。 |
| **記憶體** | 狀態必須跨 session 持久保存（而不僅是在一次對話中）。 | Claude 讀寫記憶體目錄中的檔案。在處理程序重啟後仍然存在。 |

**選擇指南：** 情境編輯和壓縮在 session 內運作——編輯修剪過期輪次，壓縮在接近限制時進行摘要。記憶體用於跨 session 的持久性。許多長時間執行的 agent 三者都用。

## Agent 的快取策略

**請先閱讀 `prompt-caching.md`。** 它涵蓋前綴比對不變式、斷點放置、靜默失效稽核，以及為何在 session 中途更換工具或模型會破壞快取。本章節僅涵蓋這些限制的 agent 特有因應方法。

| 限制（來自 `prompt-caching.md`） | Agent 特有因應方法 |
| --- | --- |
| 在 session 中途編輯系統 prompt 會使快取失效。 | 改為將 `{"role": "system", ...}` 訊息附加到 `messages[]`（無需 beta header；在支援的模型上——請參見 `prompt-caching.md` § 對話中途系統訊息）。快取前綴保持完整，模型將其視為操作者授權的指令而非使用者文字。在不支援的模型上，改為在使用者輪次中使用 `<system-reminder>` 文字區塊。 |
| 在 session 中途切換模型會使快取失效。 | 為子任務派生帶有較便宜模型的**子 agent**；讓主迴圈保持在同一個模型上。在 Managed Agents 上，這是一個 `multiagent` 名冊條目——請參見 `managed-agents-multiagent.md`。 |
| 在 session 中途新增/刪除工具會使快取失效。 | 使用**工具搜尋**進行動態探索——它是附加工具綱要而非替換，因此現有前綴得以保留。 |

多輪斷點放置請使用 `prompt-caching.md` §自動與明確斷點中所述的組合做法：在靜態系統前綴設一個明確斷點，再為對話尾端搭配頂層自動快取（在有提供自動快取的地方使用）。
